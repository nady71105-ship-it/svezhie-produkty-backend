# Свежие продукты — backend

Рабочий backend для MVP: API на Express + PostgreSQL/PostGIS + Telegram-бот.
Уже написан и проверен здесь, в этой сессии — с реальным PostgreSQL+PostGIS,
не просто «должен заработать». Дальше — что нужно сделать, чтобы это
заработало по-настоящему, с реальными людьми, бесплатно на старте.

## Что нужно от вас — 2 шага (займут вместе минут 15)

### Шаг 1. Создать Telegram-бота

1. В Telegram откройте **@BotFather**, отправьте `/newbot`.
2. Придумайте имя (например «Свежие продукты») и техническое имя,
   заканчивающееся на `bot` (например `svezhie_produkty_bot`).
3. BotFather пришлёт **токен** — длинную строку вида `123456789:AAExample...`.
   Пришлите мне его сюда, в чат (это не пароль от вашего аккаунта, только от
   бота — его в любой момент можно перевыпустить через BotFather, если что).

### Шаг 2. Завести бесплатную базу данных на Supabase

1. Зайдите на **supabase.com** → «Start your project» → войдите через GitHub
   или почту.
2. Создайте новый проект (New Project), придумайте пароль для базы —
   **сохраните его**, он понадобится.
3. В настройках проекта: кнопка **Connect** (или Project Settings → Database) →
   вкладка **Session pooler** (НЕ «Direct connection» — та строка работает
   только по IPv6, а большинство хостингов, включая Railway, его не
   поддерживают; проверено в этой же сессии). Строка выглядит так:
   `postgresql://postgres.ВАШ-PROJECT-REF:[ВАШ-ПАРОЛЬ]@aws-0-РЕГИОН.pooler.supabase.com:5432/postgres`.
4. Пришлите эту строку мне (с уже вставленным паролем вместо `[ВАШ-ПАРОЛЬ]`).

Бесплатный тариф Supabase — 500 МБ базы, этого с большим запасом хватит на
тысячи объявлений; единственный нюанс — проект «засыпает» после недели
простоя без запросов и просыпается сам при следующем обращении (на MVP это
не страшно, речь о задержке в несколько секунд на первый запрос после паузы).

## Дальше — деплой на Railway (тоже бесплатно на старте)

Это уже могу сделать я вместе с вами пошагово, когда придут токен бота и
строка подключения к базе:

1. **railway.com** → Sign up (через GitHub) → New Project → Deploy from GitHub
   repo (или Empty Project + подключение через Railway CLI, если репозитория
   на GitHub ещё нет — решим, когда дойдём до этого шага).
2. В Variables проекта добавляются переменные окружения — ровно те, что
   перечислены в `.env.example` в этой папке (`DATABASE_URL`,
   `TELEGRAM_BOT_TOKEN`, `ADMIN_TOKEN` и т.д.).
3. Railway сам определяет, что это Node.js-проект, и запускает `npm start`.
4. Первые 30 дней — $5 пробного кредита без привязки карты, дальше —
   формально $1/мес (это уже дешевле, чем самая скромная оценка ~1000₽/мес
   из раздела 14 концепта).

**Важно на будущее (раздел 15 концепта, 152-ФЗ):** и Railway, и Supabase —
не российские облака. Для закрытого теста с небольшой группой людей это
обычная практика и разумный компромисс ради скорости и нулевой цены. Но
прежде чем открывать сервис по-настоящему широкой публике, базу стоит
перенести на российский хостинг (например Timeweb Cloud, от ~900₽/мес за
самый скромный сервер) — это отдельный, не срочный шаг, сделаем его перед
настоящим запуском, а не сейчас.

## Локальный запуск (для меня/для проверки)

```bash
npm install
cp .env.example .env   # и заполнить своими значениями
node src/db/migrate.js # один раз — создаёт таблицы
npm start
```

## Структура проекта

- `src/db/schema.sql` — вся схема БД, с комментариями почему что так.
- `src/routes/` — API: объявления, пользователи, отзывы, категории, аналитика.
- `src/telegram/verifyInitData.js` — проверка подлинности данных из Mini App.
- `src/bot/bot.js` — Telegram-бот (long polling, без вебхука — см. комментарий в файле).
- `src/middleware/auth.js` — авторизация через Telegram, без своих паролей.
- `src/middleware/adminAuth.js` — простая защита `/admin/*` общим токеном.
